# 0053 · Decisions

[Back to index](README.md)

| # | Decision | Why |
|---|---|---|
| 1 | Remove the per-cluster colour completely: `ClusterEntry.color`, `ClusterProfile.color`, `color_to_store`, `set_cluster_color`, `color_swatches`, the `Color` form row, and their tests. No migration: `ClusterEntry` has no `deny_unknown_fields` (and uses `flatten`), so serde **ignores** an old `color` key on load, and the next save drops it. An entry whose only override was `color` loads as an entry with no overrides; it keeps its place in `registry.clusters` (switcher order) and is pruned on its next edit, as today. | Nothing reads the colour since 301f4f0. Project rule: no compatibility layers. |
| 2 | Split today's `Environment` enum in two. The enum is renamed **`EnvironmentTier`** (the four built-ins, unchanged serde `lowercase`, names, badges, guessing). A new **`Environment`** enum is what a cluster wears: `BuiltIn(EnvironmentTier)` or `Custom(CustomEnvironment)`. It is `Clone`, not `Copy`. | One value carries identity, look, and tier, so badges, groups, and guards read one field (`profile.environment`) with no global lookup. The tier enum keeps every exhaustive match on the safety rules. |
| 3 | Every safety rule reads the tier: `ConfirmMode::for_tier(EnvironmentTier)` replaces `for_environment`; `profile()` derives `read_only`, `confirm`, and `allow_node_shell` from `environment.tier()`. A custom environment always counts as "set in the entry" for the node-shell default (it can only be chosen explicitly). | A custom environment can never be weaker than the built-in it names. No rule is duplicated. |
| 4 | Persist a reference, resolve at profile time. `ClusterEntry.environment: Option<EnvironmentKey>`, `EnvironmentKey` = `#[serde(untagged)] BuiltIn(EnvironmentTier) \| Custom(String)`. Built-ins keep their stored strings (`"production"`); a custom one stores its name (`"QA"`). | Old files load unchanged. Any string parses (no file reset for an unknown name). The file stays readable. |
| 5 | A reference to a missing custom environment (hand edit only, or one ignored by decision 6) resolves to **Production**. The Environment dropdown then shows the stored key string (e.g. `Gone`) with nothing checked. | Fails safe: locked and type-the-name, never silently weaker. Showing the stored string tells the user what is dangling instead of pretending it is Production. |
| 6 | Custom names: trimmed, 1–16 chars, no control chars, unique among custom ones ignoring case, and not reserved ignoring case. Reserved words are **derived**, not hard-coded: `EnvironmentTier::ALL` names and badges, `BUILT_IN_GROUP_TITLES` (today's `GROUP_TITLES`, moved to `environment.rs`), and `auto`. One shared predicate, `is_reserved(name)`, serves `validate_environment_name` **and** `resolve_environment`: at resolution a custom environment whose trimmed lower-case name is reserved, or repeats an earlier custom one, is ignored (counts as missing → Production, decision 5). Badge = `name.to_uppercase()`. Unicode lookalikes (Cyrillic `Р`, full-width letters) are accepted and out of scope. | The form alone is not enough: `EnvironmentTier` is `rename_all = "lowercase"`, so with the untagged key `"production"` is built-in but `"Production"` or `"PROD"` parse as `Custom`; a hand-edited `{name: "Production", tier: "local"}` would otherwise be a Local-tier cluster wearing a red PRODUCTION badge. Duplicates would also break group-title matching in drag (`clusters_page.rs` `drop_cluster`, `DraggedCluster`). Deriving the list keeps it in step with the built-ins. |
| 7 | Store the list as `registry.environments: Vec<CustomEnvironment>` (`name`, `color`, `tier`), in creation order (= display order). Entry references match a custom name **exactly** (case-sensitive) everywhere: `resolve_environment`, `rename_environment`, `delete_environment`, `clusters_using`. | `ClusterRegistry::profile` already owns resolution; no signature change. |
| 8 | Palette = `EnvironmentColor` (today's `ClusterColor`, renamed) plus **Green**: Red `danger`, Amber `warning`, Green `success`, Blue `info`, Teal `cyan`, Purple `magenta`, Gray `muted_foreground`. Built-ins stay Production Red, Staging Amber, Development Blue, Local Gray, and are not editable. | gpui-component 0.7 `ThemeColor` has base `red/green/blue/yellow/magenta/cyan` (+ `_light`), no orange or pink. Semantic tokens match the built-ins. Read through `cx.theme()` at render, so light/dark and Zed One (0052 sets every `base.*` and semantic token) adapt with no branch. |
| 9 | A new custom environment starts as **Purple, Production tier**. | No cluster uses it yet, and the strictest tier is the safe default; the user lowers it on purpose. Purple is the first hue no built-in uses. |
| 10 | Delete: always a confirm dialog. Clusters that use it (every registry entry, loaded or not) move to `BuiltIn(its tier)`, in the same `AppSettings::update`. | Data-loss-free for behaviour: the guardrails stay identical; only the label goes. Blocking was rejected: an entry of an unloaded file could block forever with no way to fix it in the UI. |
| 11 | Rename rewrites every `Custom(old)` entry reference in the same update. Changing the tier to a **weaker** one (lower in `EnvironmentTier` order, e.g. Production → Staging) while `clusters_using > 0` opens a confirm alert (the delete pattern) naming how many clusters lose the stricter rules; a stronger or equal tier, or an unused environment, saves at once. No reorder: the list keeps creation order (a possible follow-up). | A weaker tier is the one edit here that silently loosens guardrails for clusters the user is not looking at. Reorder was not asked for. |
| 12 | Badge colour is the environment's colour (built-in: fixed; custom: chosen). The confirm tier, not the colour, is the guardrail. The Clusters dropdown labels custom items `QA · like Staging` so the tier is visible where it is chosen. | Keeps the badge rule simple; the risk hint lives in the dropdown and the Safety table. |
| 13 | Groups: built-ins in today's order (`Production`, `Staging`, `Development · Local`), then one group per custom environment in creation order. `ClusterGroup.title` and `SwitcherSection.title` become `SharedString`. Titles stay unique (decision 6), so the drag payload keeps matching groups by title. | Predictable order; no change to built-in grouping. |
| 14 | New page `SettingsPage::Environments`, between Clusters and Appearance, icon `IconName::Tag` (in the kit Lucide catalog). A view entity like `MetricsPage`, shown as one element item. Launch screen `--screen settings-environments`. | Follows the existing page pattern. The wireframe has no such page; [environments-page.md](environments-page.md) describes it. W2's `Color` row is superseded by this spec. |
| 15 | Rename commits on each valid `InputEvent::Change`, like Display name. Name inputs are rebuilt only by the page's own add and delete, and when the page opens, never on every settings change. | A rebuild on each change would reset the caret while typing (`"Pre "` trims to `"Pre"`). Only one Settings window exists, so nothing else renames. |
| 16 | `guess_environment` returns `EnvironmentTier`; the "Auto (STG)" choice and the import preview stay built-in. | A guessed custom environment would be a hidden rule. |
