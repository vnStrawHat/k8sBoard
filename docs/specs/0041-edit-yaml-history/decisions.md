# 0041 · Decisions

[Back to index](README.md)

| # | Decision | Rationale |
|---|---|---|
| 1 | No snapshot, no rollback, no ConfigMap compare, no timeline ConfigMap rows | User decision 2026-10-03. Each needs stored history; the cluster keeps none for ConfigMaps. |
| 2 | Revision history for **Deployments only** | W10 draws a Deployment. Deployments keep history as ReplicaSets, which the app already reads (0039). StatefulSets and DaemonSets use ControllerRevisions: a new kind, watch, and masking path for no drawn need. |
| 3 | The tab **embeds** the 0039 `RevisionDiffView` | Same GETs, masking, env toggle, diff rows, and texts; no second diff view. The dialog and the tab differ only in their frame. |
| 4 | Quota: **steady state, unscoped quotas, requests and limits of CPU and memory, pods**; a missing request uses the limit (the documented Kubernetes rule, quota-check.md); the reported headroom is the smallest `left / hard` fraction | The dry-run of a Deployment `PUT` never checks quota: quota admission runs when pods are created. The check is advice. Surge pods, scoped quotas (`BestEffort`, `PriorityClass`, …), LimitRange defaults, and `spec.overhead` are known ceilings, named in the code with a `ponytail:` comment. |
| 5 | Quotas come from the session's **ResourceQuotas condition feed** (`issue_feeds.rs`) | It already watches quotas for the scope; no new request. When it is off (denied, narrow scope) the check says so instead of reading the cluster. |
| 6 | "Who" = the **field manager** name of `managedFields`, shown as **inferred** | Kubernetes stores no user on an object (only the audit log, out of reach). The manager is what kubectl, Argo CD, Helm, or a CI tool set (`kubectl-edit`, `argocd-controller`, `helm`, `ci-bot`). The tooltip reads `probably {manager} · last pod-template writer (field manager)`, so nobody reads it as proof. |
| 7 | Rule: the Deployment's newest non-status `managedFields` entry that owns `f:spec` › `f:template`, used when its time is at most 60 s after and at most 30 min before the event's `last_seen` | A rollout starts right after the template write; a later write cannot have caused it. Outside the window the event source stays (today's `deployment-controller`). `ponytail:` heuristic, an exact cause needs the audit log. Known ceiling: an HPA scale of the same Deployment inside the window (a `ScalingReplicaSet` event with no template change) is also attributed to the template writer. |
| 8 | Click-to-diff: the ReplicaSet the **event message names** (`Scaled up/down replica set {name} to {n}`) against its numbered predecessor when both are listed; otherwise the **newest revision vs the one before**, newest = highest revision number | The named set is the rollout the row reports, so the diff matches the row. The Deployment controller gives a rolled-back ReplicaSet the next number, so the highest number is always the current template; no Deployment GET is needed. A scale-down of an old set during a rollout names the old set, which then diffs against its own predecessor; the subtitle shows both revision numbers. |
| 9 | One new read, `deployment_revisions(deployment, selector)`: a LIST of the namespace's ReplicaSets with `labelSelector` = the Deployment's selector (`DeploymentSummary.selector` joined by `,`, the syntax of `watch_selected_replica_sets`), then kept when their controller owner is the Deployment | The selector bounds the LIST to the Deployment's sets; the owner filter drops a set another controller owns that happens to match. The selector comes from the session's Deployment rows (the kind list, or the Deployments condition feed on Overview); an empty or `<invalid>` selector returns an empty list with no request. Summaries are built on tokio; the raw list is dropped there. |
| 10 | Timeline rows keep **reveal** except Deployment rows, which open the diff; the diff dialog gains `Go to deployment` | W3 n4 says a click opens the diff (W10). Reveal stays one click away. |
| 11 | The quota line is a **warning**, never a block; an exceeded item is also a confirm-dialog warning | The server accepts the Deployment change either way; the user decides. |
