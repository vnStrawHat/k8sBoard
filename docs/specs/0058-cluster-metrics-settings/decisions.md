# 0058 · Decisions

[Back to index](README.md)

| # | Decision | Why |
|---|---|---|
| 1 | **A second kit group, full page width, below the list and the form** (not a section inside the form column, not collapsed). Header `Metrics · {row label}` drawn like the form's section headers. | The form column is about 450 px (1000 px window − 200 px sidebar − 300 px list − gaps); `Other service` needs about 700 px (three 170 px inputs, a 90 px port, the scheme button) and a candidate's mono detail about 430 px. A group of its own is also what the kit can scroll to (decision 5). Inline, not collapsed: the section is the reason to come here, and a collapse adds state for nothing. |
| 2 | **Reach of a cluster that is not open: option (b), a one-time client on click.** Detect and Test open it with `cluster_registry::open_cluster(kubeconfig, context, &profile.proxy)` under `TEST_CONNECTION_TIMEOUT` (15 s), run the one call, and drop it. The open cluster keeps using `ActiveConnection`. | The app already has the cheap one-off client: the Clusters form's **Connection test** opens exactly this (`cluster_form::test_connection` → `open_cluster` → `ClusterConnection::open`) for any row, open or not. Option (a) would need a cross-window "Connect" that switches the main window's session from Settings (the Settings window cannot reach the shell, see `active_session.rs`) and a disabled state; (b) is one `match`, no new cluster-crate API, and lets the user set a source before ever opening the cluster. |
| 3 | **No automatic request for a cluster that is not open.** Detection starts on its own only for the open cluster, at the section's first draw (0048 fix 20). For any other row Detect and Test are clicks. | Same rule as Test connection and 0043 folder-watch: a kubeconfig from a watched folder is untrusted and may run an exec plugin; it is never probed without a click. Also avoids a `list services` per row click. |
| 4 | **One `ClusterMetricsSection` entity per Clusters page**, retargeted by `show_cluster(Some(row))` whenever the page builds a new form (selection change, Reset to defaults, row removed) and `show_cluster(None)` when nothing is selected. | The kit group needs one stable view to embed, present on the first frame (a group index that is missing on the first frame is dropped by the kit's `selected_index`, so the scroll would be lost). One row is selected at a time (`ClustersPage.selected`, one `form`), so one entity suffices. The old `follow_connection` reset becomes `show_cluster`; the `MetricsPage` state machine moves as is. |
| 5 | **Scroll by kit group index**: `SelectIndex { page_ix: Clusters, group_ix: Some(CLUSTER_METRICS_GROUP) }` with `CLUSTER_METRICS_GROUP = 1`. The group has no title, so the sidebar gets no sub-item. | The kit scrolls its page list to a group by index on the first frame of a new `Settings` state (`page_generation` bump); there is no public way to scroll inside one group. Cost: the Clusters sidebar item is not highlighted while `group_ix` is `Some` (open item 1). A titled group would add a collapsible `Clusters ▸ Metrics` sidebar entry, which contradicts "remove the Metrics page". |
| 6 | **Entry points.** The only control that opened the Metrics page is the form's `Choose on the Metrics page…` menu item; it goes with the `Metrics · Source ▾` row, since the section now sits on the same page. The Monitor range tip, the Topology Traffic tip, and `source_note` are texts on disabled controls: they change to `Settings › Clusters › Metrics`. `show_cluster_metrics(cx)` is the one helper for any future link; today its caller is the launch path in `main.rs`. No palette or keymap entry existed for the Metrics page. | The brief assumed clickable links in the Monitor and Topology; grep shows tooltips only (`monitor_tab.rs` `SHORT_HISTORY_TIP`, `topology_view.rs` `traffic_button`). Making them clickable is a UX change nobody asked for. |
| 7 | **Screens:** `settings-metrics` and `settings-metrics-fixture` are replaced by **one** `settings-cluster-metrics-fixture`. No live screen. | A live screen would have to select the open cluster before the catalog has loaded and before the session is Live (`resolve_selection` drops a selection the catalog does not list yet). The live UAT check uses `--screen settings` with a `--script` (click the row, scroll), which needs no new code. |
| 8 | **Settings model unchanged.** The entry is already per cluster: `ClusterEntry { cluster: ClusterRef, …, metrics: Option<StoredMetrics> }` in `registry.clusters` (`cluster_registry.rs`), read through `ClusterProfile.metrics` and written with `edit_entry(&mut registry, &cluster, …)`. No key, allow-list, or JSON change; `settings_keys_are_the_allow_list` is untouched. | — |
| 9 | **Reset behaviour unchanged.** The form's `Reset to defaults` already clears `metrics` with the entry (`reset_entry`); the section follows through decision 4. The settings-file reset banner (`settings_reset_banner.rs`) has nothing to do with this page. | — |
| 10 | **A failed one-time open** shows as a detection failure (`Cannot list services: {error_text}. Enter the service below.`) or as a Test result `MetricsError::Unexpected(format!("cannot connect: {}", error_text(&error)))`, displayed `the metrics request failed: cannot connect: …`. | Reuses the two existing result types; `error_text` is what Test connection and detection already show (no secret: `ClusterError` texts never carry credentials, 0002). |
| 11 | **Label of the section** is the row label (`ClusterRow.label`), not `ActiveConnection.label`. | The section is about the selected row, open or not. |
