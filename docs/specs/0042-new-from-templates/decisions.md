# 0042 · Decisions

[Back to index](README.md)

| # | Decision | Rationale |
|---|---|---|
| 1 | **Five kinds, a closed list** (`ObjectKind::is_creatable`): Namespace, ConfigMap, ResourceQuota, PodDisruptionBudget, RoleBinding | The kinds W7 gives `New`. A closed list keeps the create allow-list narrow (C3); a new kind is a reviewed code change. |
| 2 | **YAML template in an editor**, no per-kind form | W7 draws buttons only. The 0031 editor, keys, and slot already exist; a form per kind is five UIs for no drawn need. |
| 3 | A **separate small view** (`ObjectCreateView`), not a mode of `YamlEditView` | `YamlEditView` is built around a server base (`EditBase`, placeholders, rebase, 409 reload). A create has no base; mixing both would add `Option`s to every path. The new view reuses the kit editor setup, the `YAML_EDIT` key context (`ApplyEdit` on Ctrl S), the edit slot (`OpenEdit`), the discard prompt, and the 0031 panel helpers. |
| 4 | **POST with `fieldManager=k8sboard`**, no server-side apply | C8: no SSA anywhere; a create has no concurrency to guard, and the server answers 409 if the name exists. |
| 5 | **Validation twice**: `ObjectDraft::new` (user-facing errors) and `checked_operation` (re-check of the built draft) | The task asks for explicit validation in `checked_operation`; the draft type also makes a bad request unrepresentable from the app. |
| 6 | 409 on create → `Invalid { "{Kind} {name} already exists", ["metadata.name"] }`; 404 (dry-run or commit) → `Invalid { "The namespace {ns} does not exist", ["metadata.namespace"] }` | `Conflict` reads "changed since it was read" and offers a reload that has no meaning for a create; `NotFound` reads "the object no longer exists", which is wrong for an object not yet made (a POST 404s only when its namespace is missing). Mapped once in `write_error`, so the dialog, notice, and view agree. No new `WriteError` variant. A 404 on a Namespace create has no namespace in its path, so it reads `The Namespace API is not available on this cluster`. |
| 7 | **Draft warnings** (in the confirm): `PowerfulRole` when a RoleBinding's `roleRef` is ClusterRole `cluster-admin`, `admin`, or `edit`; `BroadSubject` for any Group or User subject whose name starts with `system:`; `PrivilegedPodSecurity` for a Namespace labelled `pod-security.kubernetes.io/enforce: privileged` (pods there may run privileged) | Granting broad rights by mistake is the main risk of this feature. The API server's escalation check (needs `bind` or the rights already) still applies; the warning makes the grant visible before it is sent. Warn-only (no typed name): a ServiceAccount subject in `kube-system` (`SystemNamespaceAccount`) and a ClusterRole named `system:*` (`SystemRole`). |
| 8 | Namespace in the template: the **first scoped namespace** (`scope.namespaces().first()`: `Named` or the first of `Several`, which is sorted), else `default` | The user is usually looking at that namespace; the text stays editable. |
| 9 | Name rules: Namespace a DNS-1123 **label**; ConfigMap, ResourceQuota, PDB a DNS subdomain; RoleBinding the path-segment rule (0031 decision 27) | The API server's own rules; checked locally so the error names the field before a request. |
| 10 | Server-owned fields are **refused**, not stripped | A pasted `uid` or `resourceVersion` means the text came from another object; refusing says so. `status` likewise. |
| 11 | After commit: **close, show the kind's screen, and push the notice**; no cursor move | `apply_pending_reveal` drops a reveal when a loaded list lacks the row (`app_shell.rs`), and the watch adds the new row a moment after the commit. Showing the screen lets the watch add it; waiting for the row would need a new pending state. |
| 12 | No Retry anywhere: `CreateObject` joins the edit exclusion of the dialog's Retry (`write_flow.rs`), and the view offers none after `OutcomeUnknown` | A repeat after an unknown outcome reads as a confusing 409; after a 409 or 422 the text must change first. The user checks the list. |
| 13 | **Secrets deferred** | Not in W7's `New` list. 0047 rules (write-only masked values) do not fit a YAML text editor. |
| 14 | **Dropped-field warning** after a dry-run: paths of the draft missing from the server's answer | kube 4.2 `PostParams` has no `fieldValidation`, so a misspelled field (`spec.minAvailble`) is dropped silently. `missing_paths(draft, answer)` walks the draft's leaves (lists by index; empty maps, empty lists, and `null` skipped, as the server omits them) and reports paths only, never values. Shown as `{path} is not a known field; the server dropped it` in the side panel and the confirm. An empty string is skipped like `null` (a subject with `apiGroup: ""` comes back without it). |
| 15 | **Privileged tier for risky bindings**: a RoleBinding draft with `PowerfulRole` or `BroadSubject` uses `ActionRisk::Privileged` with `expected_name: Some(binding name)` | `confirm_step` already types the name on every environment for `Privileged` (0037 node shell). A wide grant on a dev cluster is still a wide grant; typing the binding name proves the user read it. Other drafts keep `ActionRisk::Change` and the cluster's tier. On a PROD cluster a risky binding therefore types the binding name, not the cluster name, as the 0037 node shell does with the node name: the name proves the user read what is granted. |
| 16 | Confirm and audit lists are **capped**: RoleBinding subjects one per field `{Kind} {ns/}{name}`, ConfigMap keys one per field (`data[KEY]`, `binaryData[KEY]`), at most 10 each, then one `… and {n} more` field | The user must see who gets the grant; a 500-key ConfigMap must not flood the dialog or the audit line. The warning and dropped-field lines of the side panel and the confirm follow the same rule (ten, then `… and {n} more`); `metadata.finalizers` are listed too (capped), because a finalizer nothing removes keeps a Namespace from being deleted. |
